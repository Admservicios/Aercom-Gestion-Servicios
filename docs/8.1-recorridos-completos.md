# 8.1 · Validación de recorridos completos

Las pruebas de integración usan datos ficticios y sesiones separadas de Administración, Comercial, Técnica, Coordinación y Campo. Recorren las rutas y formularios de la aplicación. Las referencias de Excel, Logística y SAP se cargan como datos ficticios en Servicios.

| Caso | Recorrido comprobado |
|---|---|
| Abonado con varios equipos | Dos equipos de una planta, lavado incluido y correctivo adicional con su cotización. Los pedidos comparten una visita. Se completa el lavado y el correctivo queda parcial con un motivo visible. Se registra la factura del abono por mes y la cobertura del lavado. |
| Tercero | Solicitud técnica, precio informado por Compras, cotización, correo y OC, pedido, visita, resultado, factura posterior y cierre SAP. Una cuenta de Campo ajena no puede registrar el resultado. Un doble envío conserva el primero. Comercial no puede asentar el cierre. |
| Venta de repuestos | Cotización aprobada, envío de pedido a Logística, confirmación de entrega con remito ficticio y registro de factura. El pedido conserva el circuito sin visita. |
| Facturación y cobro previos | La factura y el cobro quedan registrados mientras el trabajo sigue abierto. Después se agenda y ejecuta la visita. Se verifican por separado los estados de facturación, cobranza y ejecución. |

En un entorno de desarrollo con PostgreSQL, se pueden ejecutar los recorridos con:

```bash
DJANGO_SECRET_KEY="$(cat .aercom-demo/django.key)" python manage.py test servicios.test_recorridos
```

## Resultado

Pasaron los cuatro recorridos y la suite completa de 62 pruebas con PostgreSQL 16.16. Docker Compose arrancó con una base vacía, aplicó las veinte migraciones de Servicios y conservó un único ticket de ejemplo al repetir la inicialización. El chequeo de Django pasó y la revisión de migraciones indicó que no hay cambios de modelo pendientes.

En Chromium se ingresó como Oficina y Campo sobre la base limpia. Se consultó un abonado con varios equipos, se completó el lavado, se verificó el rechazo del acceso de Campo a facturación y se registró una factura mensual ficticia. La revisión de vibración siguió asignada.
