# 2.1 · Entorno del piloto

## Qué se preparó

El devcontainer usa la imagen oficial `python:3.12-bookworm` de Docker Hub. Se agrega el usuario de desarrollo `vscode` para ejecutar los comandos de Codespaces sin privilegios de root. Docker Compose mantiene PostgreSQL 16 con una comprobación de disponibilidad antes del arranque de la aplicación. El contexto de construcción incluye solo el Dockerfile.

La inicialización existente prepara la clave de PostgreSQL en `.devcontainer/.env`, aplica las migraciones y genera dos claves individuales de demostración en `.aercom-demo/cuentas.json`. Esos archivos se generan localmente y están excluidos de Git. En una base de demo que ya tenga las dos cuentas, la carga vuelve a aplicar las claves del archivo local. El puerto 8000 se abre como privado desde Codespaces.

## Qué se verificó

Se construyó la imagen y arrancó Docker Compose con una copia limpia y un volumen de prueba. En este entorno, PyPI requirió el certificado de confianza de la máquina anfitriona al instalar desde el contenedor. La instalación se completó usando ese certificado, con verificación TLS activa.

Se ejecutó dos veces el arranque con migraciones y datos ficticios. Se verificaron las dos cuentas por HTTP, los estilos, `manage.py check`, la ausencia de migraciones nuevas y las dos pruebas automatizadas con PostgreSQL 16. Quedó un único ticket de ejemplo después del segundo arranque.
